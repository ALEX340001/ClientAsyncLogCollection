📄 Конфигурационный файл appsettings.json

Приложение ClientAsyncLogCollection использует JSON‑файл для задания параметров сбора логов Windows. Файл должен называться appsettings.json и располагаться в папке с исполняемым файлом (или указываться через ключ --config).

📌 Структура JSON

ПолеТипОбязательноеОписание
Domainstring❌ нетДомен (служебное поле, не влияет на сбор). Пример: "mydomain.local"
DefaultFolderPathstring❌ нетПуть к папке, куда будут сохраняться логи, если не указан UserFolderPath.
По умолчанию: "Logs" (относительно рабочей папки).
UserFolderPathstring❌ нетАльтернативная папка пользователя. Имеет приоритет над DefaultFolderPath. Удобно для переопределения через CLI (--pl).
Formatstring❌ нетФормат выходных файлов: "json" или "xml". По умолчанию: "json".
EnabledApplicationsмассив объектов✅ даСписок приложений/провайдеров, логи которых нужно собрать (см. таблицу ниже).
Flagsмассив целых чисел❌ нетУровни событий (Level): 1=Critical, 2=Error, 3=Warning, 4=Information, 5=Verbose.
Пример: [2,3,4] (ошибки, предупреждения, информация). Если массив пустой или отсутствует – не будут читаться вообще никакие события. Рекомендуется указывать явно.

📦 Элемент EnabledApplications

Каждый элемент массива — объект с двумя полями:

ПолеТипОписание
NamestringТочное отображаемое имя провайдера (как в оснастке eventvwr.msc). Пример: ".NET Runtime", "Service Control Manager".
LogstringИмя журнала Windows, в котором нужно искать события.
Допустимые значения: "Application", "System", "Security" (требуются права) и другие.
Совет: указывайте явно, чтобы избежать проблем с автоматическим определением.
📌 Примечание: если поле Log отсутствует или равно null, программа попытается определить журнал автоматически через Windows API (ProviderMetadata). Для многих провайдеров это работает, но для некоторых (например, Kernel-General) автоматика не срабатывает, поэтому настоятельно рекомендуется указывать журнал явно.

📝 Пример готового файла appsettings.json

{
  "Domain": "corp.domain.com",
  "DefaultFolderPath": "C:\\Logs\\MyApp",
  "UserFolderPath": "",
  "Format": "xml",
  "EnabledApplications": [
    { "Name": ".NET Runtime", "Log": "Application" },
    { "Name": "Service Control Manager", "Log": "System" },
    { "Name": "Microsoft-Windows-GroupPolicy", "Log": "System" },
    { "Name": "DNS Client Events", "Log": "Application" },
    { "Name": "Kernel-General", "Log": "System" }
  ],
  "Flags": [2, 3, 4]
}

⚙️ Приоритет параметров

  1. Параметры командной строки – наивысший приоритет.
  2. Значения из JSON‑файла (если не переопределены).
  3. Встроенные значения по умолчанию (Format = "json", DefaultFolderPath = "Logs").

🖥️ Параметры командной строки (CLI)

Короткий ключДлинный ключТипОписание
-c--configстрокаПуть к JSON‑файлу конфигурации
-f--formatстрокаФормат вывода: json или xml
—--defaultFolderстрокаПапка по умолчанию для сохранения логов
—--plстрокаПапка пользователя (приоритетнее defaultFolder)
—--appsсписокСписок приложений через запятую (заменяет массив из JSON)
—--flagsсписокУровни событий (1–5) через запятую
-h--help—Вывод справки

📌 Примеры вызова программы

ClientAsyncLogCollection.exe
ClientAsyncLogCollection.exe --config "C:\MyConfigs\custom.json"
ClientAsyncLogCollection.exe -f xml --pl "D:\Logs"
ClientAsyncLogCollection.exe --apps "Service Control Manager,.NET Runtime" --flags 2,3
ClientAsyncLogCollection.exe -c "settings.json" --pl "C:\Temp" --flags 4
